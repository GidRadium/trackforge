# ADR-0001: Модульный монолит + гексагональная архитектура

- **Статус:** accepted
- **Дата:** 2026-10-22

## Контекст

TrackForge — личный локальный инструмент с CLI/Python API и будущим GUI. Нужны чёткие границы, расширяемость (источники/анализаторы/рендереры) и возможность переиспользовать код как библиотеку. При этом нет команды, сервера и требований к горизонтальному масштабированию.

## Решение

Строим **модульный монолит** с гексагональной архитектурой:

- `domain` — чистые сущности/политики, без I/O;
- `application` — use cases + порты;
- `adapters` — yt-dlp, API, ffmpeg, mutagen, SQLite;
- `interfaces` — CLI, позже HTTP/GUI;
- `bootstrap` — composition root.

Зависимости: `interfaces → application → domain`; адаптеры реализуют порты; домен ничего не импортирует из внешних слоёв.

## Альтернативы

1. Микросервисы — избыточно для одного пользователя, добавляет сеть/деплой/транзакции.
2. Один слой/скрипты — быстро стартовать, но больно расширять и тестировать.
3. Полностью plugin-based ядро — гибко, но сложно типизировать и отлаживать.

## Последствия

- Нужна дисциплина импортов (`import-linter`).
- Больше файлов/абстракций на старте.
- Легче тестировать домен и заменять адаптеры.
- Позже можно вынести HTTP/GUI в отдельный процесс без переписывания домена.
