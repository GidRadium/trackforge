# ADR-0003: Content-addressed storage + SHA-256

- **Статус:** accepted
- **Дата:** 2026-10-22

## Контекст

Нужны resume, дедупликация, безопасность оригиналов и воспроизводимость. Файлы могут приходить из разных источников; одни и те же байты могут иметь разные метаданные/решения.

## Решение

- Байты хранятся в CAS по SHA-256 (`cas/ab/cd/<sha256>`), неизменяемо.
- `MediaObject` идентифицирует содержимое; `Intake` — происхождение.
- `Item` имеет собственный `item_id` (не хэш), чтобы разные источники/решения не смешивались.
- Артефакты — общий кэш по `cache_key`; item workspace ссылается на них.
- Оригиналы не изменяются; output — производные файлы.

## Альтернативы

1. Идентичность по пути — ломается при перемещении/дубликатах.
2. BLOB в SQLite — раздувает БД, плохо для больших файлов.
3. In-place тегирование — риск потери данных.

## Последствия

- Нужен GC для осиротевших объектов.
- Хэширование больших файлов — streaming.
- Дубликаты естественно дедуплицируются.
- Sidecar/decisions позволяют восстановить контекст.
