# ADR-0002: Claims/decisions вместо одного dataclass метаданных

- **Статус:** accepted
- **Дата:** 2026-10-22

## Контекст

В предыдущей попытке (`gravidrome`) был один `AudioFileTextMetadata` со всеми полями. Это не позволяло отличить факт от догадки, хранить альтернативы, объяснять решения и перезапускать интерпретацию. Разные источники дают противоречивые значения; nightcore/remix ломают наивное «одно название/один артист».

## Решение

Разделяем:

- **Observation** — сырое измерение/получение (immutable);
- **Claim** — утверждение о поле с subject/source/method/confidence/evidence;
- **Decision** — выбранное значение с альтернативами, policy, rationale, lock;
- **DecisionRecord** — снимок решений с версиями.

Claims append-only; решения пересобираемы; `unknown` — легальный результат.

## Альтернативы

1. Один metadata dataclass — просто, но теряет provenance/альтернативы.
2. Только source priority — предсказуемо, но не использует консенсус/контекст.
3. LLM как единственный арбитр — дорого/нестабильно/необъяснимо.

## Последствия

- Больше сущностей и кода.
- Нужны explain/review UI/CLI.
- Появляется audit trail и возможность калибровки.
- Feedback становится первоклассным артефактом.
