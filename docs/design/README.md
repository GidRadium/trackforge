## 1. Зачем этот каталог

Здесь фиксируется не код, а **контракты и решения**: что делает TrackForge, из каких частей он состоит, какие данные проходят через систему, где границы модулей и почему выбраны те или иные инструменты.

Документы должны быть:

- достаточно конкретными, чтобы по ним можно было писать код;
- достаточно стабильными, чтобы не переписывать их каждую неделю;
- честными: открытые вопросы не прячутся, а лежат в [`open-questions.md`](open-questions.md).

## 3. Как мы работаем

1. Сначала фиксируем **инварианты** (что не меняется) и **границы** (что не делаем).
2. Каждое существенное решение оформляем как ADR: контекст → варианты → решение → последствия.
3. Схемы данных и контракты версионируем.
4. Любой анализ сначала описываем как контракт (входы/выходы/стоимость/детерминизм), потом реализуем.
5. Документы на русском; код, имена модулей и идентификаторы — на английском (предложение, подтвердить).
6. Код не пишем, пока не согласованы видение, домен и конвейер.

## 4. Текущий фокус

Первый–пятый раунды закрыты: продукт, MVP, запись, интерфейсы, анализаторы, облачные LLM, feedback, autopilot, деградация, лицензия, форматы, ranker, источники, шаблон имени, профиль, embedding, layout, платформы и масштаб зафиксированы.

Уточнения после review: LRC/ELRC — только sidecar; ID моделей — в `config.toml`, не в коде; LLM `base_url`/`model` — в `config.toml`, API key — в `.env`, без «провайдера по умолчанию» в коде.

Документация v0.3 покрывает видение, домен, архитектуру, pipeline, storage, источники, анализ, резолв, метаданные, интерфейсы, операции, качество и roadmap. Есть glossary и 6 ADR.

Аудит противоречий выполнен: [`13-consistency-review.md`](13-consistency-review.md). Найдено 12 расхождений/пробелов, 11 исправлено, 1 принято как упрощение v1 (identity-сущности пока artifact-only).

Оценка Phase 0 spikes по интернет-бенчмаркам: [`14-phase0-spikes-assessment.md`](14-phase0-spikes-assessment.md). Ключевое: 16–18 ГБ хватает при **одной тяжёлой модели за раз**; Whisper small — безопасный default для `full`; Demucs PyTorch — только opt-in (≈1.5× длительности трека), ONNX/OpenVINO — отдельный spike; cross-encoder MiniLM QInt8 — хороший дефолт; yt-dlp/Deno и MusicBrainz rate limit — главные операционные риски.

Следующий шаг — **Phase 0 spikes**:

- проверить yt-dlp/Deno/cookies на 5–10 своих ссылках;
- проверить round-trip тегов для MP3/M4A/FLAC/OGG/Opus;
- замерить Whisper small/medium и Demucs на целевом CPU;
- проверить cross-encoder и LLM на своих примерах;
- зафиксировать MVP scope Phase 1.

Остаются менее срочные вопросы: политика плейлистов, детали теговых полей, ReplayGain, рекомендации по моделям.

## 5. Требования к среде (предварительно)

- Python 3.12+;
- `uv` для управления зависимостями и запуска;
- `ffmpeg`/`ffprobe` как внешние бинарники;
- SQLite (входит в Python);
- для части анализаторов — опциональные extras: `faster-whisper`, `demucs`, `essentia`, `torch`;
- для YouTube может понадобиться JS-runtime (например, Deno) и актуальный `yt-dlp` — уточним в `05-sources.md`.

В текущем окружении `uv` и `ffmpeg` не обнаружены; это не блокирует проектирование, но войдёт в bootstrap-инструкцию.
