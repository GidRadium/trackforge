## Роль

Ты — senior Python engineer, отвечающий за наблюдаемость длинных прогонов и
совместимость тегов. Работаешь в `trackforge` после Plan 18.1. Задача — сделать
так, чтобы пользователь видел, что происходит с каждым треком плейлиста, получал
человекочитаемый отчёт по каждому обработчику, а итоговые файлы содержали только
понятные плеерам теги.

## Цель

Во время `collection add`/`collection resume` CLI показывает один обновляемый
список треков: label, текущую стадию/операцию, измеренный прогресс, elapsed и
итоговый путь/ошибку. Обновление идёт не чаще раза в секунду и не блокирует
pipeline. После прогона CLI печатает отчёт по каждому capability: статус,
длительность, attempts, artifacts, warnings и короткий человекочитаемый результат.
Те же DTO доступны Python API/будущему GUI/SSE. Tag writer переходит на
стандартные ID3/MP4/Vorbis-поля; `TRACKFORGE_*` и прочая приватная provenance
больше не пишутся в audio tags, а остаются в sidecar.

## Контекст и инварианты

- Сейчас `EventBus` умеет `step.started/progress/finished`, но:
  - нет collection-level агрегатора и label трека;
  - `STEP_PROGRESS` кладёт процент в `message`, а не в структурное поле;
  - download progress парсится только после завершения `yt-dlp`;
  - CLI ничего не подписывает на события и печатает только финальный результат;
  - `RunStepView` не содержит длительности и человекочитаемого результата.
- Events и progress — observability, **не source of truth**. Состояние по-прежнему
  в SQLite/artifacts. Progress не пишется в БД на каждом тике.
- UI не блокирует pipeline: capability сообщает прогресс через non-blocking sink,
  board хранит только последнее состояние, renderer читает snapshot по таймеру.
- Нельзя выдумывать процент. Если операция не даёт измеренный progress — показываем
  стадию, elapsed и `…`, а не фальшивые 50%.
- `--json` печатает в stdout ровно один JSON-объект. Live-progress и отчёты идут в
  stderr; в `--json` live-progress выключен, отчёты включаются в итоговый JSON.
- Non-TTY, dumb terminal, `TERM=dumb` и `CI=1` не получают ANSI/cursor control.
- Прогресс не содержит description, lyrics, cookies, токены, query-параметры URL.
  Labels и summaries проходят ту же redaction/sanitize-политику, что sidecar.
- Tag-поля с пробелами/регистром не должны выглядеть как `TRACKFORGE_DERIVATIVE`,
  `LANGUAGE`, `REMIXER` в MP4. Для полей без переносимого стандарта используется
  sidecar/comment, а не произвольный freeform-ключ.
- `docs/design/` не изменяется. Отклонения и новая tag-матрица фиксируются здесь.

## Scope

1. **Progress DTO и порт.** Добавить `ItemProgress`, `HandlerReport`,
   `CollectionProgressSnapshot`, `ProgressSink`/`ProgressBoard`.
2. **Инструментирование.** ProcessCollection создаёт board для выбранных items;
   ProcessItem обновляет стадии; Executor отдаёт capability reports; acquisition
   получает live download progress; Whisper/Demucs сообщают измеренный прогресс.
3. **CLI renderer.** Rich Live/table со списком треков, обновление по таймеру,
   plain fallback, флаги `--progress`/`--progress-interval`/`--reports`.
4. **Handler reports.** `StepResult.summary/details`; итоговая таблица по каждому
   обработчику; те же данные в `RunResult`/`CollectionRunResult`/JSON.
5. **Tag interoperability.** Переписать mapping на стандартные ID3/MP4/Vorbis-ключи;
   убрать `TRACKFORGE_*` из audio tags; старую приватную provenance оставить в sidecar.
6. **Contracts/tests.** Unit/contract/integration/negative на progress, reports и
   raw tag mapping; проверить `ffprobe`/mutagen round-trip.

## Non-goals

- GUI/HTTP/SSE реализация — Plan 19. Здесь только transport-neutral DTO и snapshot API.
- Persist каждого progress-тика в SQLite; отчёты — in-memory текущего прогона.
  Persist/replay отчётов после рестарта — Deferred (sidecar/DB остаются truth).
- Изменение алгоритмов ASR/Demucs, новые модели, новые metadata providers.
- Перевод/переписывание lyrics, description или cover pipeline.
- Изменение sidecar schema v1 и `docs/design/`.
- Гарантия, что каждый плеер показывает каждый стандартный тег; матрица ниже —
  максимально переносимый консервативный набор.

## Контракты

### Progress DTO

```text
ProgressStatus = queued | running | cached | done | failed | skipped

ItemProgress(
  scope_id, collection_id, item_id,
  position, total,
  label,                      # title/filename/source_id; never description
  stage, stage_index, stage_total,
  status, percent | None,
  message | None,
  elapsed_ms, output_path | None,
  warnings, updated_at
)

CollectionProgressSnapshot(
  collection_id, status,
  started_at, updated_at,
  completed, failed, skipped, remaining,
  items: tuple[ItemProgress, ...]
)
```

- Публичные high-level стадии: `plan`, `acquire`, `observe`, `interpret`, `resolve`,
  `render`, `publish`; `stage_total = 7`.
- Внутри `observe` stage остаётся `observe`, а `message`/report показывает
  capability (`musicbrainz`, `whisper`, `demucs`, ...). Для неизвестного числа
  sub-операций stage index не выдумывается.
- `label` приоритет: финальный title → candidate.title → имя файла → external_id.
  Обрезается до 80 grapheme-safe символов для TTY.
- `percent` — только `0.0..1.0` из измеренного progress. Иначе `None`.
- Снимок содержит ровно выбранные items коллекции, отсортированные по position.
  Уже обработанные resume-items получают `done`/`skipped` без повторного запуска.

### ProgressSink / ProgressBoard

```text
class ProgressSink(Protocol):
    def update(self, item: ItemProgress) -> None: ...
    def handler(self, report: HandlerReport) -> None: ...

class ProgressBoard:
    def start_collection(collection_id, items) -> None
    def update(self, item: ItemProgress) -> None
    def handler(self, report: HandlerReport) -> None
    def snapshot(collection_id) -> CollectionProgressSnapshot
    def reports(collection_id) -> tuple[HandlerReport, ...]
```

- `update`/`handler` синхронные, non-blocking, never raise; ошибка UI не валит run.
- Board хранит последнее состояние по `(collection_id, position)`, а не историю.
  Память O(items + handlers).
- Renderer сам решает частоту; board не делает I/O.
- `ProcessCollection` создаёт board, передаёт sink в `ProcessItem`; при
  `collection_add`, `collection_resume`, `run_candidate`, `run_item` он доступен через
  `AsyncTrackForge.collection_progress(collection_id)`.
- Single-item `add/import` использует тот же sink с `total=1`; CLI может печатать
  одну строку или финальный отчёт.

### Structured events

`Event` получает backward-compatible поля:

```text
progress: float | None
item_position: int | None
item_total: int | None
item_label: str | None
stage: str | None
stage_index: int | None
stage_total: int | None
```

- `STEP_PROGRESS` заполняет `progress`, а не только `message`.
- `Event.to_dict()` включает `message` и все новые поля (сейчас `message` теряется).
- `EventBus` остаётся lifecycle/coarse event stream; high-frequency тики не обязаны
  попадать в history. Board — источник для renderer/GUI snapshot.
- `capability.started/finished` не добавляются: используются существующие
  `step.started/finished/failed/skipped/cached` + `HandlerReport`.

### HandlerReport

```text
HandlerStatus = succeeded | degraded | cached | skipped | failed

HandlerReport(
  scope_id, collection_id, item_id, position,
  capability_id, provider | None, kind,
  stage, stage_index,
  status, started_at, duration_ms,
  attempts, cache_hit,
  artifacts: tuple[str, ...],
  summary,                    # one human line, <= 200 chars
  details: Mapping[str, Any], # canonical JSON, no lyrics/description/secrets
  warnings, error | None
)
```

- `StepResult` получает optional `summary: str | None` и
  `details: Mapping[str, Any] = {}`. Executor превращает их в `HandlerReport`.
- Длительность считается по `time.monotonic()`; cached — `0 ms`; skipped — причина
  в `summary`/`warnings`.
- `capability_id` — manifest id (`musicbrainz_search`, `whisper`, `demucs`, ...);
  `provider` — provider/source, если известен.
- Artifacts — типы/ids, не payload. `details` не содержит lyrics, description,
  cookies, request bodies, query strings.
- Отчёт доступен в:
  - `ObservationView.step_reports`;
  - `RunResult.handler_reports`;
  - `CollectionRunResult.handler_reports`;
  - JSON-представлении этих DTO.
- Для major handlers обязательны осмысленные summaries:
  - acquire: `m4a, 3.7 MB, 231.9 s`;
  - probe: `aac, 231.9 s, 128 kbps`;
  - MusicBrainz: `matched "Collide" — End Of The Dream (0.96)`;
  - AcoustID: `2 candidate(s), best 0.97` или причина skip;
  - Cover: `1280×720 JPEG, source_thumbnail/CAA`;
  - LRCLIB/description: `plain+synced, 3.4 KB` / `plain from description`;
  - ASR: `en, 42 segment(s), 7.4× realtime`;
  - Demucs: `vocals 25.2%, drums 19.1%, bass 18.0%, other 37.7%`;
  - interpret: `24 claim(s), derivative=nightcore`;
  - resolve: `5 unknown field(s), 2 warning(s)`;
  - render: `m4a, 3.7 MB, bundle abcd…`;
  - publish: путь.

### CLI progress

Новые флаги `collection add|resume` и single `add`:

```text
--progress auto|rich|plain|off     # default auto
--progress-interval FLOAT          # default 1.0; clamp 0.25..10.0
--reports full|summary|off         # default full for TTY, summary for --json
```

- `auto`: `rich` если stderr — TTY и не `--json`; иначе `plain`.
- `rich`: Rich `Live` + таблица, один ряд на item, обновление in-place не чаще
  `progress-interval`. Никаких `print` внутри render-loop.
- `plain`: только переходы `queued→running→done/failed/skipped`, без процентов на
  каждый тик; одна строка на переход, без ANSI.
- `off`: live-строки не печатаются; финальный отчёт и итог остаются.
- `--json`: live off; stdout — один JSON-объект; progress/reports не загрязняют stdout.
- Пример rich-таблицы (формат может уточняться, инвариант — in-place и один ряд):

```text
[ 1/10] Collide                    observe  [3/7]  MusicBrainz      42%   00:07
[ 2/10] Chaos                      resolve  [5/7]  policy          done   00:31
[ 3/10] Rebirth                    queued
...
```

- После завершения:

```text
Handler report — [1/10] Collide (Rock Goes Nightcore feat. End Of The Dream)
  acquire       succeeded   4.2s  m4a, 3.7 MB, 231.9 s
  probe         succeeded   0.1s  aac, 231.9 s, 128 kbps
  musicbrainz   succeeded   0.3s  matched "Collide" — End Of The Dream (0.96)
  acoustid      skipped     0.0s  invalid API key
  source_cover  succeeded   0.4s  1280×720 JPEG, source_thumbnail
  ...
```

- В конце коллекции — aggregate: по каждому capability count/duration/status.
- Ctrl+C/cancel: board фиксирует `failed`/`cancelled`, renderer останавливается,
  финальный отчёт показывает уже завершённые handlers.

### Download/ASR/Demucs progress

- `AcquireOptions` получает `progress: Callable[[float, str | None], None] | None`
  (не сериализуется). `AcquireItem` прокидывает callback в acquirer.
- `YtDlpClient.download` перестаёт ждать `subprocess.run` ради прогресса: читает
  stdout `--newline` построчно, парсит `TF_PROGRESS` по мере поступления и вызывает
  callback не чаще 4 раз/сек. Финальный `CompletedProcess`-эквивалент сохраняет
  returncode/stdout/stderr; timeout/cancel работают как раньше.
- Whisper: progress по `segment.end / duration` при streaming transcribe; если
  длительность неизвестна — stage/elapsed без процента.
- Demucs: progress по обработанным сегментам, если API даёт callback; иначе только
  stage/elapsed. Не эмулировать проценты.
- Render/probe/providers: stage start/finish; percent `None`, если нет измерения.

### Tag interoperability

`TAG_MAPPING_VERSION = "canonical-v2"`.

Правило: в audio tags пишутся только стандартные поля формата или
MusicBrainz/Picard-совместимые identifier-ключи. `TRACKFORGE_*` не пишутся.
Приватная provenance (item id, decision id, source id, derivative list, original
raw title) остаётся в sidecar.

|---|---|---|---|
| title | TIT2 | ©nam | TITLE |
| artists | TPE1 | ©ART | ARTIST |
| albumartist | TPE2 | aART | ALBUMARTIST |
| album | TALB | ©alb | ALBUM |
| date | TDRC | ©day | DATE |
| originaldate | TDOR | freeform `ORIGINALDATE` (Picard) | ORIGINALDATE |
| track/total | TRCK | trkn | TRACKNUMBER/TRACKTOTAL |
| disc/total | TPOS | disk | DISCNUMBER/DISCTOTAL |
| genre | TCON | ©gen | GENRE |
| bpm | TBPM | tmpo | BPM |
| key | TKEY | freeform `KEY` (Picard) | KEY |
| language | TLAN | ©lan | LANGUAGE |
| label | TPUB | freeform `LABEL` (Picard) | LABEL |
| catalog | TXXX:CATALOGNUMBER | freeform `CATALOGNUMBER` (Picard) | CATALOGNUMBER |
| barcode | TXXX:BARCODE | freeform `BARCODE` (Picard) | BARCODE |
| isrc | TXXX:ISRC | freeform `ISRC` (Picard) | ISRC |
| compilation | TCMP | cpil | COMPILATION |
| comment | COMM | ©cmt | COMMENT |
| description | TXXX:DESCRIPTION | freeform `DESCRIPTION` (Picard) | DESCRIPTION |
| lyrics | USLT | ©lyr | LYRICS |
| copyright | TCOP | cprt | COPYRIGHT |
| license | TXXX:LICENSE | freeform `LICENSE` (Picard) | LICENSE |
| source URL | WOAS | ©url | SOURCE |
| qualifier | TIT1 (content group) | ©grp | GROUPING |
| remixer | TPE4 | — (уже в ©ART/comment) | REMIXER |
| originalartist | TOPE | ©ope | ORIGINALARTIST |
| source id | — | — | — |
| originaltitle | — | — | — |
| derivative list | — | — | — |
| item/decision IDs | — | — | — |

- Для MP4 `©lan`, `©ope`, `©url`, `©grp` обязаны round-trip через mutagen и быть
  видны `ffprobe -show_entries format_tags`. Если конкретный mutagen/ffprobe не
  сохраняет атом — поле не пишется в audio, остаётся в sidecar/comment; fallback
  фиксируется тестом и warning `tag_not_supported:<format>:<field>`.
- `REMIXER`/`ORIGINALARTIST`/`LANGUAGE` в MP4 **не писать**. В Vorbis это
  Picard/Xiph-совместимые uppercase-ключи, они остаются.
- `TRACKFORGE_DERIVATIVE` и все `TRACKFORGE_*` удаляются из writer/reader mapping.
  При перезаписи файла writer удаляет старые managed `TRACKFORGE_*` (migration).
- Sidecar `trackforge` block и `identity.derivative` не меняются.
- `TagSet` больше не отдаёт `trackforge` mapping в writer; поле остаётся только
  для sidecar. `metadata_document()` не меняется.
- Reader читает новые стандартные поля; старые `TRACKFORGE_*` игнорируются.
- Round-trip verify проверяет только записанные canonical-поля.

## Тесты

- **unit:** board snapshots/coalescing/labels/positions; stage ordering; percent
  `None` when unavailable; handler report durations/status; summaries truncation;
  no secrets/lyrics/description in details; board never raises.
- **unit/CLI:** rich renderer updates same table (fake console/clock), interval
  throttling, plain fallback, `--progress off`, `--json` has clean stdout only.
- **contract:** Event.to_dict includes structured progress; ProgressSink error does
  not fail run; RunResult/CollectionRunResult JSON includes handler_reports; API
  `collection_progress` returns same snapshot as board.
- **integration (fake yt-dlp):** 2-item playlist; first download emits incremental
  progress; final board shows queued→running→done, labels, output paths; handler
  reports contain acquire/observe/resolve/render/publish; one failed item doesn't
  stop the other.
- **tag interop:** generate each format, write full TagSet, assert raw keys:
  - MP3: TPE4/TOPE/TIT1/TLAN/WOAS; no `TXXX:TRACKFORGE_*`;
  - M4A: `©ope`, `©lan`, `©url`, `©grp`; no freeform `LANGUAGE`/`REMIXER`/
    `TRACKFORGE_*`;
  - FLAC/Ogg: LANGUAGE/REMIXER/ORIGINALARTIST/GROUPING; no `TRACKFORGE_*`;
  - ffprobe sees title/artist/album/date/language/grouping;
  - reader round-trip and `writer.verify` pass.
- **negative:** renderer crash/closed stdout doesn't fail run; non-TTY has no ANSI;
  fake percent never appears when capability reports none; old TRACKFORGE tags are
  removed on rewrite; duplicate controls/long labels truncated.
- **no network:** all HTTP/yt-dlp/media fixtures local; no real lyrics.

## Acceptance criteria

- [ ] CLI показывает по одному обновляемому ряду на выбранный item с label,
      стадией `x/7`, измеренным процентом (или `…`), elapsed и итогом.
- [ ] Обновление не чаще `--progress-interval` (default 1 s), не блокирует
      download/ASR/Demucs и не добавляет новые строки на каждый тик.
- [ ] `--progress plain/off`, non-TTY и `--json` работают без ANSI и line spam;
      `--json` stdout остаётся одним объектом.

## Stop conditions / decision gates

- Нужно менять `docs/design/` или sidecar schema — стоп, вынеси в handoff.
- Нужен GUI/HTTP/SSE — Plan 19, не расширяй 18.2.
- Нужно выдумывать прогресс или парсить stdout нестабильного формата — лучше
  stage/elapsed без процента.
- Renderer начинает блокировать pipeline/писать в stdout JSON — стоп, переделай
  на board + stderr.
- Стандартный тег не подтверждается mutagen/ffprobe — не пиши его в audio,
  оставь sidecar и зафиксируй warning.
- Тесты требуют сети/реальных lyrics — стоп, synthetic fixtures.
