# Plan 18.1: Metadata quality для реальных плейлистов

- **Статус:** ready
- **Тип:** Post-MVP
- **Зависит от:** Plan 12, Plan 14, Plan 18
- **Разблокирует:** [Plan 18.2](18.2-progress-reports-tags.md), Plan 20
- **Оценка:** L
- **Риск:** высокий
- **Решение:** D11 — для derivative main artist = remixer, original artist = featured

## Роль

Ты — senior Python engineer, отвечающий за качество metadata pipeline. Работаешь в
`trackforge` после Plan 18. Задача — довести реальный YouTube-плейлист от «файлы
скачались» до пригодных для библиотеки title/artist/lyrics/genre/cover, не расширяя
scope на identity/release-нормализацию, ASR и GUI.

## Цель

После обработки реального плейлиста: filename и title очищены от source noise;
MusicBrainz/LRCLIB получают `source.metadata` и нормализованный title/artist; lyrics
извлекаются из явной секции `Lyrics:` в description и/или LRCLIB; genres ограничены;
cover плейлиста скачан в CAS и применяется при `playlist_first`; derivative-треки
подписаны как `Remixer feat. Original - Title (Qualifier)`; финальные warnings одинаково
видны в CLI и sidecar.

## Контекст и инварианты

- Реальный прогон Plan 18 выявил:
  - `{642} Nightcore (End Of The Dream) - Collide (with lyrics)` попал в filename,
    хотя LLM предложил `Collide (Nightcore)`;
  - `description` содержал `Lyrics:`, но `metadata.lyrics` остался `null`;
  - MusicBrainz/LRCLIB получили `no_query`, потому что `source.metadata` не входил в
    `StepContext.inputs`;
  - `genre` собрал YouTube-категории вроде `Lyrics (Website Category)`;
  - `playlist_first` не применил обложку плейлиста: URL не был в CAS;
  - stale warning `album is unknown` остался в CLI после `tag_basis`, а sidecar
    `warnings` был пуст.
- Source metadata — доказательство, не истина. Original title/description/uploader
  сохраняются в source snapshot и sidecar.
- Source noise (`07-resolution.md` §6.2) не попадает в title: `(Lyrics)`,
  `(Official Video/Audio)`, `{number}`, channel-префиксы.
- Uploader канала `... Nightcore`/fan/curator — не original artist. Для derivative он
  становится remixer/main по D11; original artist берётся из initial tags,
  `Original title:`/description, MusicBrainz или LLM; иначе `unknown`.
- D11 (решение пользователя): для nightcore/remix main artist — **remixer/channel**,
  original artist — featured. Целевой filename:
  `Rock Goes Nightcore feat. End Of The Dream - Collide (Nightcore).m4a`.
  Это осознанное отклонение от предложения `07-resolution.md` §7.1; `docs/design/`
  не меняется, решение фиксируется здесь и в README D11.
- Original artist не теряется: он остаётся в `artist` list, `metadata.originalartist`,
  `comment` и sidecar provenance.
- Lyrics из description — только plain text без таймкодов; LRC/ELRC — только из
  LRC-провайдера/ASR. Нельзя выдавать строки без таймингов за synced lyrics.
- Cover применяется только как CAS hash; URL не пишется в `artwork`.
- Providers не валят run: ошибки — видимая деградация.
- `docs/design/` не изменяется. Тесты не ходят в сеть; fixtures синтетические, без
  реальных copyrighted lyrics.

## Scope

1. Optional inputs в pipeline: MB/LRCLIB получают `source.metadata.v1`, local path не
   ломается.
2. `source_identity`: единый нормализатор title/artist/qualifier для provider query и
   claims.
3. Description lyrics: явная `Lyrics:`-секция → plain `lyrics` claim.
4. Genre hygiene: очистка source tags, лимит и policy priority.
5. Playlist cover: один fetch на коллекцию → CAS hash → item context.
6. Diagnostics: финальные warnings без stale/info-шума, provider 4xx с redacted body.
7. Derivative credits: remixer main, original featured, qualifier в filename.

## Non-goals

- ASR/Whisper, LRC alignment, переводы lyrics.
- Release/recording identity-таблицы и MB release normalization.
- Новые providers, ban evasion, channels, >500 items, параллельная обработка.
- Настраиваемый `original_first` режим — Deferred; 18.1 фиксирует remixer-first для derivative.
- GUI/HTTP collection UI.
- Изменение `docs/design/`; реальные lyrics в fixtures.

## Контракты

### Source identity

```text
NormalizedSourceIdentity(
  title, artist, qualifier, source_title, confidence, warnings
)
normalize_source_identity(title, uploader, description) -> NormalizedSourceIdentity
```

- `Original title:`/`Original song:` искать по всем строкам description, не только
  первой. Формат `Artist - Title`; album — отдельный claim.
- Поддерживать `{N} Nightcore (Artist) - Title (with lyrics)`,
  `Artist - Title (Nightcore)`, хвосты `(Lyrics)`, `(Official Video/Audio)`, `[HD]`.
- Удалять leading `{N}`/`[N]`, channel-префиксы и noise; `Nightcore` — qualifier,
  не часть title.
- При confidence `>=0.7` SourceMetadataInterpreter добавляет `title`/`artist` claims
  с source `source_title_parser`, confidence `0.8`/`0.7`.
- Грязный raw source title **не** добавляется как title claim; original остаётся в
  snapshot, `source_metadata` artifact и sidecar provenance. Чистый raw title можно
  оставить claim'ом.
- Provider query использует original artist из normalizer, а не remixer: D11 влияет
  на финальные tags/filename, но MusicBrainz/LRCLIB ищут оригинальную запись.
  Uploader становится query-artist только для non-derivative или если original
  artist не найден.

### Optional inputs

```text
CapabilityManifest.optional_requires: tuple[ArtifactRef, ...] = ()
```

- Planner добавляет provider optional input в DAG, если artifact доступен, и не
  блокирует capability, если его нет (local file без source metadata).
- Executor включает optional artifact в `StepContext.inputs`; ordering гарантирует,
  что source metadata observer выполнился раньше.
- Cache key учитывает optional artifact hash, если artifact присутствует.
- MB/LRCLIB объявляют `source.metadata.v1` optional; CoverArt остаётся зависимым от MB.
- Если есть title, но нет artist: MB может искать по title; LRCLIB skip с отдельным
  warning `lyrics_artist_unknown`, не общий `no_query`.

### Lyrics

```text
DescriptionLyrics(text, section, confidence, warnings)
extract_description_lyrics(description) -> DescriptionLyrics | None
```

- Явная строка `Lyrics:`/`Lyric:` (case-insensitive).
- Захват до footer-маркеров (`Original art`, `Follow`, `More ...`, `VK:`,
  `My soundcloud`, `All arts`, `Business`, `Nightcore mixes`) или до 256 KB.
- Отбрасывать пустые/короткие (<80 символов) и URL-only блоки.
- Блок с `[mm:ss]` не выдавать как plain: либо `synced_lyrics`, либо skip с warning;
  в 18.1 — skip, чтобы не загрязнять synced fields.
- Claim: `field=lyrics`, source `source_description`, method
  `description_lyrics/v1`, confidence `0.55`, evidence artifact id.
- Merge: synced LRCLIB > plain LRCLIB > description. Text не дублировать между
  `lyrics`, `synced_lyrics`, `elrc`.

### Genre

```text
normalize_source_genres(tags, title, uploader) -> tuple[str, ...]
```

- Trim/NFC, dedupe case-insensitive, максимум 6 значений.
- Отбрасывать `Music`, `Lyrics`, `... (Website Category)`, `... (TV Genre)`,
  `... (Film Genre)`, channel/uploader, title-фрагменты, URL, значения >40 символов.
- Policy priority: `user_lock → user → musicbrainz → llm → item.genre → unknown`.
- Если richer provider/LLM данных нет, используются cleaned source genres.

### Derivative credits and naming

```text
DerivativeCredits(
  remixer, original_artist, title, qualifier, comment, confidence, warnings
)
build_derivative_credits(transformations, uploader, normalized_identity, claims)
```

- Применять к `nightcore`, `sped_up`, `slowed`, `remix`; для `cover` оставить
  cover-artist main, original — в `originalartist`/comment.
- `remixer` = очищенный uploader/channel; `original_artist` = normalizer из
  `Original title:`/description, затем LLM claim.
- Если известны оба:
  - `artist` display = `"{remixer} feat. {original_artist}"`;
  - claims: remixer `role=main, order=0`, original `role=featured, order=1`;
  - `title` = чистый original title (`Collide`);
  - `qualifier` = `Nightcore` (или Remix/Sped Up) — отдельно, не внутри title;
  - `comment` = короткая provenance-строка `Nightcore by <remixer>; original by <original>`;
  - sidecar `metadata.artist` = `[remixer, original]`, `metadata.remixer` = remixer,
    `metadata.originalartist` = original.
- Целевой filename при default naming:
  `Rock Goes Nightcore feat. End Of The Dream - Collide (Nightcore).m4a`.
  Достигается парой `artists=[remixer, original]`, `title=Collide`,
  `qualifier=Nightcore` и существующим join-правилом `feat.` в `naming_values`.
- `TagSet` получает optional `remixer`/`originalartist`; sidecar — те же поля.
  Mapping: ID3 `TXXX:REMIXER`/`TXXX:ORIGINALARTIST`, MP4 freeform
  `----:com.apple.iTunes:REMIXER`/`ORIGINALARTIST`, Vorbis `REMIXER`/`ORIGINALARTIST`.
- Если original неизвестен: `artist` = remixer, filename без `feat.`; warning.
  Если remixer неизвестен: fallback original main; remixer только в comment.
  Если значения совпадают — не дублировать.
- Не добавлять `Nightcore` в title, если он уже есть в qualifier/filename.
- Non-derivative tracks не меняются. `original_first` — Deferred в 18.2.

### Playlist cover

- `CollectionCoverService.resolve(collection) -> str | None` (CAS hash).
- Первый `cover` claim: HTTP GET с `UrlSafetyGuard`, лимитом размера, проверкой JPEG/PNG,
  записью в CAS. Один fetch на коллекцию.
- Hash добавляется item context как `artwork` claim (source `playlist_cover`,
  confidence `0.7`) и применяется при `playlist_first`.
- Ошибка/offline/disabled covers → warning и fallback на per-item `source_thumbnail`;
  run продолжается.
- Cover URL не попадает в `artwork` decision или filename; тесты — injected fake fetcher.

### Diagnostics

- Warnings строятся после последнего resolve/tag-basis; warnings полей, которые больше
  не unknown, удаляются.
- `llm:extract: added N claim(s)` — debug/event, не warning.
- `path_unavailable` для URL — ожидаемая деградация, не дублировать в каждом item.
- `SidecarData.warnings` получает финальные observation/provider/render warnings;
  CLI и sidecar согласованы.
- Provider 4xx context: `status`, redacted `body_excerpt` (до 512 символов, без
  headers/cookies/query). AcoustID 400 → user_action проверить ключ.

## Тесты

- **unit:** title/artist parser; `{N}`; `(with lyrics)`; `Original title:` на 5-й
  строке; отсутствие artist → unknown; lyrics parser/footer/LRC-skip; genre-лимит;
  cache key optional input; derivative credits и точный filename
  `Rock Goes Nightcore feat. End Of The Dream - Collide (Nightcore).m4a`.
- **contract:** optional input не блокирует capability при отсутствии artifact;
  MB/LRCLIB optional source metadata; sidecar warnings = финальные; remixer/
  originalartist поля sidecar и tag mapping.
- **integration (fake yt-dlp):** 2-item playlist с noisy title и synthetic lyrics;
  чистые filenames/title, artist из `Original title`, derivative filename,
  lyrics в sidecar/tag, album плейлиста, genre <=6, playlist cover hash.
- **negative:** provider 400 с redacted body; cover fetch fail → warning, run completes;
  local file без source metadata не теряет MB/LRCLIB; пустая/битая lyrics-секция.
- **no network:** fake HTTP/yt-dlp и synthetic text; реальные lyrics не коммитить.

## Acceptance criteria

- [ ] MB/LRCLIB получают source metadata; при наличии title/artist запрос выполняется,
      а не падает в общий `no_query`.
- [ ] Local file без source metadata не теряет metadata observers.
- [ ] `{642} Nightcore (Artist) - Title (with lyrics)` нормализуется; `(with lyrics)`
      не попадает в title/filename; original сохраняется в sidecar.
- [ ] `Original title:` из любой строки description используется для artist/title.
- [ ] Nightcore/remix подписан `remixer feat. original`; filename ровно
      `Rock Goes Nightcore feat. End Of The Dream - Collide (Nightcore).m4a`;
      original не теряется в sidecar/tags.
- [ ] `title` не содержит `(Nightcore)`; qualifier хранится отдельно и не дублируется.
- [ ] Явная `Lyrics:`-секция даёт plain lyrics в sidecar/tags; LRC-блок не становится
      plain; synced fields не загрязняются.
- [ ] Genre <=6, без `... (Website Category)`/TV/film-категорий.
- [ ] Playlist cover скачивается один раз, лежит в CAS, применяется при
      `playlist_first`; при ошибке run продолжается с warning.
- [ ] Console и sidecar warnings согласованы; stale album warning после tag-basis
      отсутствует; claim-count info не выдаётся за warning.
- [ ] Provider 4xx содержит redacted status/body excerpt и понятный user_action.
- [ ] Ruff/format/mypy/lint-imports/полный pytest зелёные; `docs/design/` не изменён.
- [ ] Fixtures не содержат реальных copyrighted lyrics.

## Stop conditions / decision gates

- Нужно менять `docs/design/` — стоп, вынеси противоречие в handoff.
- Нужен ASR/identity graph/новый provider — Deferred, не расширяй 18.1.
- Provider 400 из-за невалидного ключа — warning/user_action, без перебора ключей.
- Тесты требуют сети или реальных lyrics — стоп, переделай на synthetic fixtures.
- Lyrics-парсер не отделяет текст от рекламы надёжно — лучше skip/unknown, чем мусор.
- Один item ломает весь run из-за metadata quality — стоп, исправь per-item degradation.
